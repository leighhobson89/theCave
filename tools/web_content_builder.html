Content Form

Field rules — which fields apply to which content type

Every field below lives in exactly one place: the fields here in Content Form are used identically by all five content types, and everything else lives in its own type's panel further down. Nothing is duplicated or shared across panels, so there's nothing to conflict — if a field is visible in an active (non-greyed) panel, filling it in affects that record; if a panel is greyed out, its fields are disabled and ignored, no matter what's typed into them.

Panels grey out automatically the moment you pick a different Content Type above, except Evidence Fields and Progress Evidence, which stay active for every type — any record can award evidence, and every record gets progress evidence.

Progress Evidence

Mandatory for every content type: Preview and Inject are both blocked until the id has been allocated and an image has been chosen. Both flags must be true for the item to show in the noticeboard envelope — with developer enabled off it stays hidden even when activated is on. The image is prefilled as ./assets/photos/progressEvidenceImages/[progressEvidenceId].png and follows the id if it is re-allocated — pick a photo only when the file is named something else. Either way a file that isn't there yet simply falls back to a placeholder card in game.

Ids are five digits: a service control digit then a four-digit sequence within that service — 0 Zoom Search, 1 Library, 2 Police, 3 Archives, 4 Standalone, 5 received faxes. So 43222 is a standalone page and 33333 is an archives record. Changing the Content Type re-allocates the id, because it belongs to the new service's block. Everything is recorded in assets/progressEvidence.json, one language-neutral file for the whole game — nothing is invented at runtime.

†Appears as a column in this content type's search results table.
