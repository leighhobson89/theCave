# Codebase Audit — 2026-08-10

A full read-through of the application code, looking for dead legacy code and
inefficient functions, with a hard constraint: **no behavioural change**.

Supersedes the earlier `docs/evidence-webcontent-audit.md` (2026-08-07), whose
conclusions are folded into [architecture.md](architecture.md).

explanatory comments and a fetch cache. The structural win is real even where
the line count is flat.

## Verification

- Baseline: the existing 7 Playwright tests were run **before** any edit and passed.
- The same 7 tests passed after every change set, and pass now.
- A new spec, `tests/regression-smoke.spec.js`, covers the refactored areas the existing suite did not reach (Notes, Paint, all four web services, address-history replay, language switching, story-window retitling, save/load round-trip). 9 tests, all passing. **16/16 total.**
- The rewritten flood fill was differentially tested against the original implementation over 500 randomised bitmaps and produces byte-identical output.
- `node --check` passes on all ten application modules.

Two initial failures in the new spec turned out to be wrong expectations on my
part, not regressions: committing a page title has never refreshed the tab's
`aria-label` until the next render. The tests were corrected to assert the real,
preserved behaviour.

## 1. Removed: the Evidence JSON Builder tool

Deleted, as requested:

- `tools/debug_json_string_tool.html` (259 lines)
- `tools/debug_json_string_tool.js` (357)
- `tools/evidence_builder_server.js` (399)
- `tools/EVIDENCE_BUILDER_TOOL_MANUAL.md` (137)
- the `node tools/evidence_builder_server.js` auto-approve entry in `.vscode/settings.json`

`evidence_builder_server.js` was the inject API for that page and had no other
client, so it went with it. Nothing in the game or the remaining tools
referenced any of it — verified by a repo-wide search. The Web Content Builder
had already taken over writing localized evidence catalogs, so no capability was
lost.

## 2. Removed: dead exports and unreachable code

**`constantsAndGlobalVars.js`** — `debugFlag`, `debugOptionFlag`, `stateLoading`,
`autoSaveOn`, `pauseAutoSaveCountdown`, `resetAllVariables()` (empty body),
`getGameStateVariable()`, `setOldLanguage()` / `getOldLanguage()` and the
`oldLanguage` variable, `getLanguageChangedFlag()` / `setLanguageChangedFlag()`
and its variable, `getDesktopWindowBaseZIndex()`,
`getCurrentDesktopWindowZIndex()`, `setCurrentDesktopWindowZIndex()`,
`getCanvasWidth()` / `getCanvasHeight()` / `getCanvasAspectRatio()` and the
`GAME_CANVAS_*` constants they wrapped (nothing in this game renders to a
canvas of that size).

**`webContentManager.js`** — the entire default search/authentication path:
`defaultSearch()`, `defaultAuthenticate()`, `getDefaultAccount()`,
`buildSessionFromAccount()`, `buildHelpers()`, `textIncludes()`,
`recordMatchesAnyText()`, plus `getWebsiteIds()`, `setActiveWebsite()`,
`getActiveWebsite()` and `activeWebsiteId`. All four sites define their own
`search`, and none read the `helpers` bundle or the active-website getters.
`search` and `buildPage` are now validated in `registerWebsite()` instead, so a
misconfigured site fails loudly at registration rather than silently falling
back.

**`desktopWindow.js`** — the description-panel branch
(`showDescriptionPanel`, `descriptionPanelHeightRatio`,
`descriptionHostElement`, `setDescriptionContent()`) was never enabled by any
caller; also `getContentHostElement()`.

**`ui.js`** — `getFacsimilePendingReport()`, `refreshAllPhotosWindows()`,
`refreshAllReportsWindows()`, and the `computerWindowController` bookkeeping
variable (written and null-checked, never read).

**`game.js`** — `gameLoop()`.

**`saveLoadGame.js`** — the file-download auto-save branch (dead: the only
caller passes `isManualSave = true`, and its filename was `ChipShopSave_…`,
left over from another project) together with `getCurrentTimestamp()` and
`padZero()`; the `<input type="file">` load path (no UI ever triggers it) and
its `FileReader` plumbing; `validateSaveString()`;
`handleFileSelectAndInitialiseLoadedGame()`; `initialiseLoadedGame()`;
`checkForLanguageChange()`. The two remaining functions are now direct.

**`index.html`** — jQuery, Popper and Bootstrap's JavaScript bundle were loaded
from CDNs but never used (no `$`, no `data-toggle`, no Bootstrap component).
Bootstrap's **CSS** is still loaded; only the JS went. The redundant
`<script type="module">` tags for `game.js`, `localization.js` and
`constantsAndGlobalVars.js` were dropped too — `ui.js` imports all three, and ES
modules are fetched and evaluated once per URL regardless.

## 3. De-duplicated

- **`ui.js` ↔ `webContentRegistry.js`.** `ui.js` carried private copies of `createBrowserInlineLink`, `appendDelimitedLinkText`, `normalizeStandaloneContent` (= `normalizeLines`), `normalizeStandaloneImages` (= `normalizeImages`) and an inline re-implementation of `createImageGallery`. The registry versions are now exported and imported. Standalone-page galleries and inline links are guaranteed identical to service-page ones.
- **Notes and Paint** were two near-identical paged-document implementations across both files. They now share one model-driven set of helpers (`NOTES_PAGE_MODEL` / `PAINT_PAGE_MODEL` in `ui.js`, `NOTES_PAGE_SPEC` / `PAINT_PAGE_SPEC` in `constantsAndGlobalVars.js`) covering defaults, reads, writes, index clamping, tab-row construction and tab-row sync.
- **Photos and Reports windows.** `openPhotosWindow()` and `openReportsWindow()` were 58 near-identical lines each; they are now two config objects over one `openEvidenceCarouselWindow()`. Their content builders share `createEvidenceControlsHost()`, `createEvidenceDescriptionPanel()` and `createEvidenceMagnifierOverlayHost()`.
- **Paper styles.** `applyReportPaperStyle` / `applyPhotoPaperStyle` collapsed onto one `applyPaperStyle()`.
- **Catalog lookups.** `getReportCatalogEntry` / `getPhotoCatalogEntry` collapsed onto one `getCatalogEntryForEvidence()`.
- **Measurement sync.** `syncEvidenceTitleWidth` / `syncPhotoCaptionWidth` / `syncPhotoDescriptionHeight` collapsed onto `syncMeasuredDimension()`, and the triple that always ran together became `syncPhotoMountChrome()`.
- **Facsimile payloads.** `sanitizeFacsimileReport` and `buildFacsimileReportFromConfig` shared a copy-pasted source normalizer; it is now `normalizeFacsimileSource()`, alongside a `trimmedOr()` helper for the very common `String(x || fallback).trim() || fallback` idiom.
- **Descriptions.** The `report` and `photo` branches of `getDescriptionTextByEvidence()` differed only in which catalog to consult and which label to print.
- **Web service pages.** The four page builders each hand-rolled the replay listener, the Enter-key handler, the login panel and the search-result rendering. These are now `wireReplayListener()`, `wireEnterKeySubmit()`, `createAuthPanel()` and `runSiteSearch()`.
- **Repetitive wiring.** The five language buttons became one loop over a shared `LANGUAGE_BUTTON_KEYS_BY_CODE` map used by both `ui.js` and `game.js`; the three desk-folder click handlers became one loop; the facsimile and computer hotspot blocks became `wireDesktopObjectTrigger()`; the nine-branch `if` chain in `refreshOpenWindowLocalization()` became the `DESKTOP_WINDOW_LOCALIZATION_BY_KIND` table; the ~65-line `setElementsLanguageText()` became a lookup table.

## 4. Rewritten for efficiency

**Paint flood fill** — was a 4-connected fill that pushed a **new two-element
array per visited pixel** and re-read four bytes per comparison. Filling a large
area of the 1024 × 640 canvas allocated on the order of millions of short-lived
arrays. It is now a scanline fill over a `Uint32Array` view of the ImageData:
one integer compare per pixel, whole horizontal spans consumed at a time, and a
flat array of integer indices as the work queue. Verified byte-identical on 500
randomised bitmaps.

**Evidence collection cloning** — `getEvidenceCollection()` deep-clones every
item via `JSON.parse(JSON.stringify(…))`.

- `showPreviousCarouselImage` / `showNextCarouselImage` / `showPreviousReport` / `showNextReport` each called it **purely to read `.length`**, cloning the whole collection on every arrow click. They are one `stepEvidenceCarousel()` using `getEvidenceCount()`.
- `getCurrentEvidence()` cloned the entire collection to return one item. It now resolves the active id and clones only that item.

**Localization fetch** — `initLocalization()` re-fetched `localization.json` on
*every* language change. It is fetched once and the promise is reused.

**`Intl.DateTimeFormat` construction** — the CaveOS clock built a new formatter
**every second**; the desk calendar built one on every language change. Both are
now module-level constants.

**`getElements()` churn** — `setElementsLanguageText()` and `setGameState()`
called `getElements()` dozens of times per invocation; both now destructure once.

## 5. Corrected

One string key was repaired: `refreshOpenWindowLocalization()` looked up
`"backgrotheArnieTragedyundStory"` — a botched find-and-replace of
`backgroundStory` → `theArnieTragedy`. Since `localize()` returns the key when
it is missing, changing language while the story window was open replaced its
title with that literal garbage string. It now uses `"theArnieTragedy"`, the
same key `openStoryWindow()` already uses for the same window. This is a text
repair, not a behavioural change, and is covered by a test.

## 6. Found but deliberately not changed

Each of these is a real defect whose fix would change behaviour or existing save
data, so they are documented instead. See
[architecture.md §18](architecture.md#18-known-issues).

1. **The story evidence collection is keyed by the string `"undefined"`**, because `STORAGE_KEYS.BACKGROUND_STORY` was never defined. Confirmed at runtime. Self-consistent, so the game works; the debug window's per-collection view shows an empty `theArnieTragedy` bucket. Defining the constant would orphan the story evidence in every existing save, so it needs a migration. A long explanatory comment now sits on `STORAGE_KEYS`.
2. **`openNotesWindow()` returns nothing**, so `openComputerWindow()`'s `if (notesWindow)` guard never fires and a CaveOS Notes window is neither tracked in `appWindows` nor closed with the computer, leaving a stale controller in `activeDesktopWindows`. One-line fix, but it adds a second close sound.
3. **The zoom readout is initialised to "3/5"** while there are four zoom levels.
4. **`showNotifcation` is misspelled**, and is a public global used by tests and console workflows.
5. **`localize()` evaluates `${…}` template expressions with `eval`.** No shipped string uses it. Left in place as an intentional feature hook rather than removed as legacy.
6. **`getFacsimileState()` still emits a legacy singular `pendingReport` field** that nothing reads. Removing it would shrink saves slightly but changes the saved shape; the input-side legacy fallback is what actually matters and is retained either way.

## Follow-up: login and browser-history changes (same day)

Four requested behavioural changes, made *after* the audit above. Unlike the
audit these are deliberate behaviour changes. Each was confirmed against the
running game before being changed.

**1. Logins now persist.** *Confirmed:* the session reset not just on closing the
computer but on merely navigating away to another site and back —
`createAuthPanel()` unconditionally signed in the default guest account on every
render. It now does so only when `getSession()` reports no session at all. Since
`webContentManager` is created once at module load, logins now survive
re-navigation, closing Netscape, and closing the computer.

**2. Log Out buttons added** to Police Records and the Canada Newspaper Archive.
They sign back in as the site's default guest account (`public` level 0 /
`free`) and clear the credential fields, rather than clearing the session. Both
panels are CSS grids, so the two buttons are wrapped in a
`.browser-auth-actions` flex row (one new CSS rule) to sit side by side.

**3. Usernames are now case sensitive.** *Confirmed:* `J.FLETCHER` / `oscar123`
signed in successfully, because username matching went through `textEquals()`,
which lower-cases both sides. Passwords were already exact. Both sites now share
`findAccountForCredentials()`, which compares username and password exactly and
requires both to be non-empty; only surrounding whitespace is trimmed from the
username.

**4. Browser address history.** *Confirmed:* the history was in fact already
retained across a computer close **and** already captured in the save payload —
so the reported symptom had a different cause. Two real defects were crowding
real entries out of the ten available slots:

- `about:welcome` was pushed on **every** browser open, so a few opens filled the list with the home page. It is now never recorded.
- Entries were never de-duplicated, so one repeatedly visited URL could occupy several slots. `setBrowserAddressHistory()` now de-duplicates by URL, moving a revisited URL to the most-recent position and carrying its newer replay data. This applies to restored saves as well as live pushes, so existing saves are cleaned up on load.

`pushAddressHistoryEntry()` re-reads the canonical list after writing, so the
browser window's local copy can no longer drift from the saved one. The
window-local `ADDRESS_HISTORY_LIMIT` was removed in favour of the single
`BROWSER_ADDRESS_HISTORY_LIMIT` in `constantsAndGlobalVars.js`.

Four new tests cover these (20 passing in total).

### Follow-up: persist logins into the save (same day)

After the above, the request was extended: website logins should also survive
save/load, not just an in-session computer close.

`webContentManager.js` gained `getSessionsSnapshot()` / `restoreSessionsSnapshot()`
/ `clearSessions()`. Restoring **replaces** every session rather than merging
on top, so loading a save reproduces exactly the logins (or lack of them) that
existed when it was made.

The wiring needed one indirection: `webContentManager` is a factory
(`createWebContentManager()`), not a singleton module like `evidenceManager.js`,
and its one instance is owned by `ui.js`. `captureGameStatusForSaving()` /
`restoreGameStatus()` live in `constantsAndGlobalVars.js`, which `ui.js`
already imports — importing back from `constantsAndGlobalVars.js` to `ui.js`
would be circular. So `constantsAndGlobalVars.js` now exposes
`registerWebContentSessionsProvider()`, and `ui.js` calls it once at startup
with the manager's snapshot/restore functions. Save/load call through that
registration instead.

New Game calls `webContentManager.clearSessions()` directly (no indirection
needed there, since `ui.js` already holds the instance).

Verified end to end through the *real* UI, not just the in-memory helpers: log
in, click the actual Save button, click New Game (session gone, confirmed at
the UI), click Load and paste the save string back in, confirm the login and
its access level are both restored. One new test added (21 passing in total).

While verifying this, `tests/report-magnifier.spec.js` was found missing from
the working tree (present at HEAD, absent on disk) — not a change made in this
session. It was restored from HEAD before the final test run.
